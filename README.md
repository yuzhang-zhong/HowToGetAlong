## 每条建议长这样

以下是[第 2 章第 1 条](book/02-吵架别吵出事.md)的格式摘录，省略部分请以原条目为准：

```markdown
### 1. 吵到心跳加速、说不出整句话时，叫暂停并约好半小时后回来
<!-- 成本标签: 难受=少 时间=少 毅力=些 收益=大 口径=关系质量 -->
- 成本：硬着头皮说「我需要停一下」。
- 说人话：吵到身体接管嘴巴的时候，心跳加快、耳朵像关上了，只剩下想赢……
- 收益：夫妻冲突对话研究发现，生理唤起水平与婚姻不满相关……
- 证据等级：B
- 来源：Levenson RW, Gottman JM (1983). Marital Interaction. JPSP. https://doi.org/10.1037/0022-3514.45.3.587
- 备注：暂停前约好回来谈的时间，避免对方把暂停理解成冷处理……
```

这条标为 B，不表示「半小时」经过试验证实；原条目明确区分生理唤起研究与暂停恢复时间的经验数字。只读标题或话术，会漏掉这类限制。

## 证据与核实

### 证据分级

| 等级 | 含义 |
| --- | --- |
| A | 有可查的具体数字，来源为荟萃分析、大型队列或随机对照试验（RCT）；法律条目引用法条或官方文件原文。 |
| B | 有研究支持，但没有确切数字；或依据来自小样本、单项研究、观察性或相关性设计。 |
| C | 来自作者经验或公认做法，缺少直接研究文献。 |

274 条中 A 级 126 条、B 级 122 条、C 级 26 条。关系研究里能给出清晰数字的证据较少，因此分级按证据本身来定：观察性研究没有确切数字或交叉验证时最高为 B；流行说法追不到一手文献时标 C；复制失败的说法（如「手机摆在桌上就毁掉对话」）会降级并注明。

条目写法、口径、成本标签和排序规则，见[写作规范](docs/写作规范.md)。性价比档的当前实现是 `index.html` 中的 `COST_W`、`BEN_W` 和 `tierOf`。有争议的条目会列出反方证据；尚未核实的会标注「待人工复核」。

不同口径之间不折算、不排序：关系质量、心理健康、时间精力、人身安全、人身自由、寿命和金钱不是一把尺子。证据等级也不是对一个人或一段关系的评分；安全章按危险信号与行动优先级排列，不计算性价比档。

### 文献核实

> **种子版说明**：全部条目经过三轮 AI 文献检索核实，原文全文尚未逐篇人工复核。引用前请打开来源核对；标注「待人工复核」的条目仍需优先检查。核实过程见[核实记录](docs/核实记录/)。

## 让 AI 照书回答

仓库附有中文 skill：[skills/relationship-guide](skills/relationship-guide/)。安装后，直接问「朋友借钱不还怎么开口」「吵架吵到失控怎么办」「他这样算不算家暴」。它会先检索相关条目，再按书中的规则排序回答并注明章节和条目；查不到时会直接说明。遇到正在发生的家暴、自杀念头或未成年人受侵害，先提供资源和眼下能做的一步。

- **Claude Code / Codex**：安装方法见 [skill 说明](skills/relationship-guide/README.md)。
- **对话式助手（如 Muse）**：把 `book/` 各章作为知识库上传，再把 [SKILL.md](skills/relationship-guide/SKILL.md) 全文贴进系统提示词。
- **只能填写系统提示词的助手**：粘贴[纯提示词精选版](skills/relationship-guide/PROMPT-ONLY.md)。里面收录 30 条常用建议和第 4、16 章全部 30 条安全建议；其他问题会明确说明未收录。

AI 答复仍须回到原条目的来源和备注核对，不能代替专业判断。

## 自己跑一份

**只想阅读不需要运行命令**，直接用[在线检索或离线版](#检索与离线阅读)。需要修改、校验或自己部署时，可开启 GitHub Pages 使用检索页，也可以在本地构建：

需要 Git、Node.js（CI 使用 Node.js 20）和 Python 3（用于本地服务）。克隆时保留仓库的 LF 换行：

```bash
git clone --config core.autocrlf=false https://github.com/yuzhang-zhong/HowToGetAlong.git
cd HowToGetAlong
node tools/offline/build.mjs      # 离线单文件：dist/HowToGetAlong.html
node tools/build-prompt-only.mjs  # 生成纯提示词精选版
node tools/validate.mjs           # 校验条目格式，CI 也会运行
python -m http.server 8000        # 最后启动服务：http://localhost:8000/
```

**Windows 换行提示：** 当前校验器要求章节使用 LF 换行；Git 自动转换为 CRLF 后会出现「标题行无法解析」及计数错误。上方 `--config core.autocrlf=false` 为这份克隆保留 LF。若已有克隆遇到这些错误，可在另一个空目录按上方命令重新克隆，保留原目录中的修改。

当前版本校验通过时应看到 `274 条 · A126 B122 C26 · 0 个警告`。构建后打开 `dist/HowToGetAlong.html`，或在本地检索页搜索「道歉」，检查条目、证据等级与来源；校验通过只说明格式和计数一致，文献仍需参照[核实记录](docs/核实记录/)人工复核。

本地服务会持续占用当前终端；按 `Ctrl+C` 停止，或另开一个终端运行构建命令。

## 贡献与翻译

欢迎纠错、复核来源、补充建议和翻译，不需要先写新章节：

1. **先提问题**：通过 [Issues 表单](https://github.com/yuzhang-zhong/HowToGetAlong/issues/new/choose)提交纠错、新建议或翻译问题。
2. **修改内容**：提交 PR 前先读[写作规范](docs/写作规范.md)。新增条目要附核实记录；研究主张须有一手来源，经验类条目可以标 C，并在备注里说明经验依据。
3. **提交前校验**：修改正文后运行 `node tools/validate.mjs`；按改动需要重新生成离线版和纯提示词精选版。格式通过不代表文献已经复核。

简体中文正文是内容底本；英文界面和 README 便于浏览仓库，**不代表全书已有英文译本**。正文翻译按[翻译指南](docs/translation-guide.md)逐章提交到 `translations/<语言代码>/book/`，保留章号和条目号，并注明中文源文件及对应 commit。发布前需要对照中文条目复核数字、证据等级、安全步骤和适用范围；未经复核的译文不能标为正式版本。
